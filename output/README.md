# Guide to scripts and output files

## Start here

For the final answer to the research question, read [final_evaluation/evaluation_summary.md](final_evaluation/evaluation_summary.md). It reports the **2025 test**, where the frozen selected model achieved **11.805358% lower MAE** than persistence on 361 shared dates. Use [evaluation_plot.png](final_evaluation/evaluation_plot.png) for the final prediction figure. For how the model was chosen, read [model_selection.md](model_selection.md).

**Training (2021-2023)** estimates model parameters. **Validation (2024)** selects the model/settings. **Refitting (2021-2024)** estimates final parameters after selection. **Testing (2025)** measures final performance without selecting new settings. Validation improvement (9.67%) and test improvement (11.81%) are different results.

## What each script/notebook does

The notebooks are the original detailed versions. No extra preprocessing script is needed. Execute them using the root README's instructions, followed by the Python scripts in the order below.

| Order | File in scripts/ | Purpose and main outputs |
| --- | --- | --- |
| 1 | preprocessing_without_interpolation.ipynb | Reads the five raw ZIPs; selects corrected older POC 23/method 736 and later POC 3/method 636; requires >=18 hourly readings; resolves repeated summaries; preserves every calendar date. Writes the corrected no-fill CSV, leaving missing PM2.5 blank. The included original POC-3 no-fill CSV is a comparison reference, not regenerated by this notebook. |
| 2 | preprocessing_with_interpolation.ipynb | Reconstructs both observed histories, checks them against the no-fill reference CSVs, and creates both forward-filled alternatives. Despite its name, it does not perform linear interpolation. Preserves actual values in PM2.5_Original and tracks estimated inputs. |
| 3 | model_training.py | Splits years, creates training plots/lag comparisons, and coordinates 152 ARIMA/SARIMA candidate fits across the four datasets. Writes validation predictions, rankings, logs, and comparison tables. Does not evaluate 2025. |
| Helper | validation_models.py | Imported by model_training.py. Fits candidates on training data, forecasts validation dates using only earlier observations, keeps fitted parameters fixed, and compares MAE on identical observed scoring dates. Do not run separately. |
| 4 | model_diagnostics.py | Recreates selected-model validation predictions and examines training innovations, convergence warnings, error patterns, and parameter-root magnitudes. Writes diagnostics; does not retune the model or evaluate 2025. |
| 5 | refit_selected_model.py | Verifies the frozen selection, then fits ARIMA(2,1,3) on 2021-2024. Saves the final model, parameter estimates, input history, fit summary, and version/checksum metadata. Does not search settings or score 2025. |
| 6 | evaluation.py | Loads the final model; forecasts each 2025 date before incorporating its measurement; calculates the observed previous-day baseline; scores identical eligible dates. Writes final predictions, metrics, summary, and plot without retuning. |

## How to read the file formats

- **CSV:** tables; open in a spreadsheet or read with pandas. A blank measurement is missing, not zero.
- **JSON:** structured settings or numerical summaries; readable in a text editor.
- **PNG:** figures ready to view or use in the presentation.
- **MD:** Markdown explanation pages rendered on GitHub.
- **TXT:** plain-text fit summaries or dependency lists.
- **PKL:** saved Python model, not a text report. Load only trusted models with the documented environment.

## Files directly under output/

| File | What it means |
| --- | --- |
| README.md | This file guide. |
| split_summary.csv | Calendar, observed, and missing counts for train/validation/test. Test availability is not test performance. |
| training_lag_correlations.csv | Training-only correlation with readings 1-30 calendar days earlier, plus pair counts. Dates are preserved across gaps. Exploratory correlation is not proof of seasonality. |
| validation_fit_log.csv | Corrected/no-fill candidate attempts, convergence/exclusion status, warnings, elapsed time, and MAE where a fit succeeded. |
| validation_model_comparison.csv | Corrected/no-fill candidates and baseline ranked by 2024 MAE. Lower MAE is better. |
| validation_predictions.csv | Actual 2024 concentrations, previous-day baseline, a shared scored flag, and one prediction column per successful candidate. Predictions exist on more dates than are eligible for scoring. |
| validation_selection.json | Corrected/no-fill validation winner, orders/trend, baseline MAE, score count, and environment versions. test_evaluated=false describes this validation stage only. |
| poc_comparison_all_models.csv | No-fill results comparing original POC 3 with corrected history, for all successful candidates and baselines. |
| poc_comparison_best_by_family.csv | Compact original/corrected no-fill comparison: best ARIMA, best tested weekly SARIMA, and baseline in each dataset. |
| gap_filling_comparison_all_models.csv | All four history/gap-handling combinations and their successful candidate/baseline validation results. |
| gap_filling_comparison_best_by_family.csv | Compact four-way comparison: best candidate in each model family and baseline for each dataset. |
| model_selection.md | Why the final approach was selected, diagnostic limitations, refit/evaluation protocol, and completed test result. |
| reproducibility_check.md | What was verified in the clean environment, results reproduced, and verification limits. Includes the later restoration of the original notebooks. |

Comparison-table fields: order=(p,d,q), seasonal_order=(P,D,Q,s), trend=c means a constant and n means none, validation_mae is in ug/m3, improvement_percent is relative to persistence, and scored_days is the shared number of observed dates. dataset distinguishes original/corrected history; missing_data distinguishes no filling/forward filling. Rows for persistence_baseline are benchmarks, not fitted ARIMA models.

## diagnostics/

| File | What it means |
| --- | --- |
| diagnostic_summary.json | Selected-model convergence, warnings, AR/MA root magnitudes, validation errors, negative forecast count, and interpretation notes. A root close to magnitude one can indicate sensitivity. |
| training_model_summary.txt | statsmodels fit report for the selected model fitted on 2021-2023: parameter estimates and model diagnostics. This is not the final refit. |
| validation_errors.csv | Daily actual, prediction, baseline, actual-minus-prediction error, absolute errors, and scoring eligibility. Positive signed error means underprediction. |
| validation_error_lag_correlations.csv | Whether validation forecast errors are associated with errors on earlier calendar dates; exploratory diagnostic, not a formal significance test. |
| validation_largest_errors.csv | Largest scored validation misses, useful for discussing sudden pollution changes. |
| validation_monthly_errors.csv | Scored counts and model/baseline MAE by validation month, plus mean signed error. |
| selected_model_diagnostics.png | Diagnostic panels examining training innovations and validation errors. Departures from normality or remaining error patterns are limitations, not a reason to tune on test data. |

## final_evaluation/

| File | What it means |
| --- | --- |
| evaluation_predictions.csv | All 365 test dates: actual PM2.5, model forecast, observed previous-day baseline, scoring eligibility, and absolute errors on scored dates. Three dates lack measurements; one further date lacks a previous-day baseline, leaving 361 scoring dates. |
| evaluation_metrics.json | Final scored count, model/baseline MAE, percentage improvement, 10% threshold, and whether the goal was met. This is the source for final presentation numbers. |
| evaluation_summary.md | Human-readable final protocol and results, with the prediction plot. |
| evaluation_plot.png | Actual concentrations, model forecasts, baseline, and scored observations over 2025. |

For presentation, prioritize evaluation_metrics.json, evaluation_plot.png, gap_filling_comparison_best_by_family.csv, and the two training-data explanatory plots. Use the diagnostic outputs to explain limitations. The complete audit files remain available for reproducibility.
